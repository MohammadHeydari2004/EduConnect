# سامانه جامع مدیریت آموزشی EduConnect

## معرفی پروژه

**EduConnect** یک سامانه تحت وب یکپارچه (Single Page Application) است که با هدف مکانیزاسیون و مدیریت هوشمند فرایندهای آموزشی، ارتباطی و نظارتی میان **دانشجویان، اساتید و مدیران گروه** طراحی و پیاده‌سازی شده است. این پروژه با بهره‌گیری از معماری ماژولار و فناوری‌های مدرن فرانت‌اند، محیطی متمرکز برای مدیریت کلاس‌ها، جلسات، حضور و غیاب، تکالیف، اطلاعیه‌ها و گزارش‌های تحلیلی فراهم می‌آورد. هسته داده‌ای این سامانه بر پایه یک API شبیه‌سازی‌شده (Mock API) با استفاده از `json-server` استوار است که قابلیت توسعه و اتصال به بک‌اند واقعی را بدون تغییر در لایه سرویس‌دهی دارا می‌باشد.

> **نسخه فعلی:** `1.7.0` — این نسخه، تکامل‌یافته‌ی نسخه `1.6.0` است و شامل بازنگری بنیادین در یکپارچگی تایپ‌ها، افزودن قابلیت‌های بصری جدید برای تشخیص وضعیت‌های زمانی، و بهینه‌سازی الگوهای مدیریت حالت می‌باشد.

## تکامل پروژه: از نسخه `1.6.0` تا نسخه `1.7.0`

### ۱. یکپارچه‌سازی بنیادین تایپ شناسه (Unified String ID)

| حوزه                      | نسخه قبل (`1.6.0`)                | نسخه فعلی (`1.7.0`)           |
| :------------------------ | :-------------------------------- | :---------------------------- |
| تایپ `ID`                 | `number \| string`                | `string` (صرفاً رشته‌ای)      |
| مقایسه شناسه‌ها           | `String(a) === String(b)`         | `a === b` (مستقیم)            |
| تبدیل در فرم‌ها           | `Number(value)` / `String(value)` | بدون نیاز به تبدیل            |
| تایپ `classId` در اطلاعیه | `ID \| 0`                         | `ID`                          |
| شناسه‌ها در `db.json`     | عددی (`1`, `2`, `3`)              | رشته‌ای (`"1"`, `"2"`, `"3"`) |

**هدف:** با یکسان‌سازی تایپ شناسه‌ها به `string`، کلیه تبدیل‌های اضافی (`String()`, `Number()`) از بین رفته و کد تمیزتر، خوانا‌تر و کم‌خطاتر شده است. این تغییر، ریشه‌ی اصلی بسیاری از باگ‌های مقایسه‌ای را به‌طور کامل حذف کرده است.

### ۲. قابلیت‌های بصری جدید

| قابلیت                    | توضیح                                                                                                       |
| :------------------------ | :---------------------------------------------------------------------------------------------------------- |
| **نشانگر ددلاین منقضی**   | در جدول تکالیف، ددلاین‌هایی که تاریخ آن‌ها گذشته است با رنگ قرمز و برچسب «منقضی شده» مشخص می‌شوند           |
| **نشانگر ارسال با تأخیر** | در صفحه‌ی پاسخ‌های تکلیف، اگر زمان ارسال دانشجو پس از ددلاین باشد، برچسب «ارسال با تأخیر» نمایش داده می‌شود |

### ۳. بهبود الگوی مدیریت حالت در حضور و غیاب

| حوزه            | نسخه قبل                                      | نسخه فعلی                                               |
| :-------------- | :-------------------------------------------- | :------------------------------------------------------ |

- **فرم‌ها:** `ClassForm`, `AssignmentForm`, `SubmissionForm` بدون تبدیل `Number()`.

## ویژگی‌های کلیدی سامانه

### ۱. مدیریت کاربران و کنترل دسترسی (RBAC)

- احراز هویت امن و مدیریت نشست (Session) کاربران.
- تفکیک دقیق سطوح دسترسی برای سه نقش اصلی: **مدیر گروه (Admin)**، **استاد (Teacher)** و **دانشجو (Student)**.
- قابلیت جستجو، فیلتر، ایجاد، ویرایش و تغییر وضعیت (فعال/غیرفعال) کاربران.
- جلوگیری از حذف یا غیرفعال‌سازی آخرین مدیر سیستم.
- جلوگیری از تغییر وضعیت حساب کاربری خود.

### ۲. مدیریت کلاس‌ها و جلسات آموزشی

- تعریف کلاس‌های درسی با تعیین ظرفیت، استاد مربوطه و لیست دانشجویان.
- ایجاد و مدیریت جلسات (Sessions) برای هر کلاس به تفکیک تاریخ.
- نمایش وضعیت کلاس (فعال/غیرفعال) و آمار تکمیل ظرفیت.
- دسترسی مستقیم به تکالیف هر کلاس از صفحه جزئیات.
- اعتبارسنجی ظرفیت در فرم ایجاد/ویرایش کلاس.

### ۳. سیستم حضور و غیاب هوشمند

- ثبت وضعیت حضور دانشجویان (حاضر، غایب، با تأخیر) به ازای هر جلسه توسط استاد.
- محاسبه خودکار درصد حضور و غیاب هر دانشجو در هر کلاس.
- مشاهده تاریخچه حضور و غیاب توسط دانشجو در پروفایل اختصاصی.
- نوار پیشرفت بصری برای نمایش درصد حضور.
- الگوی بهینه‌شده‌ی همگام‌سازی حالت در زمان رندر.

### ۴. مدیریت تکالیف و ارزیابی (Assignments)

- تعریف تکلیف با تعیین عنوان، توضیحات و مهلت ارسال (Deadline) توسط استاد.
- امکان ارسال پاسخ (Submission) توسط دانشجو و پیگیری وضعیت آن.
- سیستم نمره‌دهی و ارائه بازخورد (Feedback) توسط استاد برای هر پاسخ ارسال‌شده.
- **تشخیص بصری ددلاین منقضی‌شده** (جدید در نسخه `1.7.0`).
- **تشخیص بصری ارسال با تأخیر** (جدید در نسخه `1.7.0`).
- ویرایش تکلیف بدون حذف پاسخ‌های موجود.
- دسترسی ادمین به نمره‌دهی و مشاهده پاسخ‌ها.

### ۵. سامانه اطلاعیه‌رسانی هدفمند

- ایجاد اطلاعیه با قابلیت تعیین مخاطب خاص (کل سیستم، یک کلاس خاص، یا نقش‌های ویژه).
- ردیابی وضعیت مشاهده (Seen/Unseen) اطلاعیه‌ها توسط کاربران هدف.
- بازنشانی وضعیت مشاهده هنگام ویرایش اطلاعیه.
- فیلترینگ هوشمند بر اساس نقش، کلاس و مخاطب هدف.
- نمایش اطلاعیه‌های ایجادشده توسط خود کاربر.

### ۶. داشبورد و پروفایل کاربری

- **پروفایل دانشجو:** نمای کلی از آمار حضور، درصد شرکت در جلسات و تاریخچه کامل.
- **پروفایل عمومی:** نمایش اطلاعات کاربری، نقش و وضعیت حساب.

## ساختار دایرکتوری پروژه (Architecture)

پروژه بر اساس اصل جداسازی دغدغه‌ها (Separation of Concerns) سازماندهی شده است:

```text
src/
├── components/          # کامپوننت‌های قابل استفاده مجدد
│   ├── common/          # کامپوننت‌های مشترک (Header, Sidebar, Loading, EmptyState)
│   └── ui/              # کامپوننت‌های UI پایه (Button, Modal, Table, Card, ...)
├── context/             # مدیریت وضعیت سراسری (AuthContext, AuthProvider)
├── data/                # داده‌های ثابت و پیکربندی‌های اولیه
├── layouts/             # چیدمان‌های اصلی صفحه (MainLayout)
├── pages/               # کامپوننت‌های سطح صفحه دسته‌بندی‌شده بر اساس ماژول
│   ├── announcements/   # ماژول اطلاعیه‌ها
│   ├── assignments/     # ماژول تکالیف و پاسخ‌ها
│   ├── attendance/      # ماژول حضور و غیاب
│   ├── auth/            # صفحه ورود
│   ├── classes/         # ماژول کلاس‌ها و جلسات
│   ├── dashboard/       # داشبورد
│   ├── profile/         # پروفایل کاربری
│   └── users/           # مدیریت کاربران
├── routes/              # تعریف مسیرها و محافظ‌های دسترسی
├── services/            # لایه ارتباط با API
│   ├── api/             # تنظیمات Axios و API پایه
│   └── modules/         # سرویس‌های اختصاصی هر ماژول
├── types/               # تعاریف نوع و اینترفیس‌های TypeScript
└── utils/               # توابع کمکی و ابزارهای کاربردی
```

## راهنمای نصب و راه‌اندازی

### پیش‌نیازها

- **Node.js** نسخه `18.x` یا بالاتر
- **npm** نسخه `9.x` یا بالاتر

### مراحل اجرا

**۱. نصب وابستگی‌ها:**

```bash
npm install
```

**۲. راه‌اندازی سرور شبیه‌سازی داده (ترمینال اول):**

```bash
npm run server
```

> این دستور یک RESTful API محلی روی پورت `3001` ایجاد می‌کند.

**۳. اجرای محیط توسعه فرانت‌اند (ترمینال دوم):**

```bash
npm run dev
```

> پروژه روی پورت `5173` در دسترس خواهد بود.

**۴. ساخت نسخه نهایی (Production Build):**

```bash
npm run build
npm run preview
```

## ملاحظات فنی و توسعه

- **یکپارچگی تایپ‌ها:** با تغییر تایپ `ID` به `string`، کلیه تبدیل‌های اضافی حذف شده و سامانه در برابر ناهمگونی داده‌ها مقاوم شده است.
- **مدیریت خطا:** تمامی درخواست‌های شبکه با مکانیزم‌های مدیریت خطا (Try/Catch) و نمایش پیام‌های مناسب به کاربر پوشش داده شده‌اند. تشخیص خطاهای شبکه (`ERR_NETWORK`, `ECONNABORTED`) به‌صورت اختصاصی پیاده‌سازی شده است.
- **اعتبارسنجی:** فرم‌ها دارای اعتبارسنجی در سمت کلاینت (Client-side Validation) جهت جلوگیری از ارسال داده‌های ناقص یا نامعتبر هستند.
- **واکنش‌گرایی:** رابط کاربری با استفاده از کلاس‌های کاربردی Tailwind CSS برای نمایش بهینه در دستگاه‌های موبایل، تبلت و دسکتاپ بهینه‌سازی شده است.
- **معماری سرویس‌محور:** کلیه درخواست‌های HTTP در لایه `services` متمرکز شده‌اند و تغییر بک‌اند (از Mock به واقعی) بدون تغییر در لایه نمایش امکان‌پذیر است.
- **الگوهای بهینه مدیریت حالت:** در `AttendancePage` از الگوی همگام‌سازی در زمان رندر (`prevSessionId`) به‌جای `useEffect` استفاده شده که کارایی و قابلیت پیش‌بینی را افزایش می‌دهد.
- **نشانگرهای زمانی:** تشخیص خودکار ددلاین‌های منقضی‌شده و ارسال‌های با تأخیر بدون نیاز به منطق سمت سرور.
