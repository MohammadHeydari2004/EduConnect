# سامانه جامع مدیریت آموزشی EduConnect

## معرفی پروژه

**EduConnect** یک سامانه تحت وب یکپارچه (Single Page Application) است که با هدف مکانیزاسیون و مدیریت هوشمند فرایندهای آموزشی، ارتباطی و نظارتی میان **دانشجویان، اساتید و مدیران گروه** طراحی و پیاده‌سازی شده است. این پروژه با بهره‌گیری از معماری ماژولار و فناوری‌های مدرن فرانت‌اند، محیطی متمرکز برای مدیریت کلاس‌ها، جلسات، حضور و غیاب، تکالیف، اطلاعیه‌ها و گزارش‌های تحلیلی فراهم می‌آورد. هسته داده‌ای این سامانه در حال حاضر بر پایه یک API شبیه‌سازی‌شده (Mock API) با استفاده از `json-server` استوار است که قابلیت توسعه و اتصال به بک‌اند واقعی را بدون تغییر در لایه سرویس‌دهی دارا می‌باشد.

> **نسخه فعلی:** `1.6.0` — این نسخه، تکامل‌یافته‌ی نسخه اولیه (`0.0.0`) است و شامل بازنگری‌های اساسی در معماری تایپ‌ها، بهبود جریان‌های کاربری، رفع باگ‌های منطقی و ارتقاء تجربه کاربری می‌باشد.

## تکامل پروژه: از نسخه `0.0.0` تا نسخه `1.6.0`

نسخه فعلی (پروژه ۳) نسبت به نسخه اولیه (پروژه ۲) دچار تحولات ساختاری و عملکردی قابل‌توجهی شده است. در ادامه، مهم‌ترین این تغییرات به تفکیک حوزه ارائه می‌گردد:

### ۱. بازنگری بنیادین در سیستم تایپ‌ها (Type System Overhaul)

| حوزه                                 | نسخه قبل (`0.0.0`)    | نسخه فعلی (`1.6.0`)              |
| :----------------------------------- | :-------------------- | :------------------------------- |
| تایپ شناسه (`ID`)                    | `number` (صرفاً عددی) | `number \| string` (انعطاف‌پذیر) |
| تایپ `classId` در فرم اطلاعیه        | `number`              | `number \| string`               |
| تایپ `authorId` در فرم اطلاعیه       | `number`              | `ID`                             |
| تایپ `currentUserId` در جدول کاربران | `number`              | `ID`                             |
| مقایسه شناسه‌ها                      | مقایسه مستقیم (`===`) | مقایسه نرمال‌شده (`String()`)    |

**هدف:** این بازنگری، سامانه را در برابر ناهمگونی داده‌های ورودی از سمت سرور (مانند دریافت شناسه‌های رشته‌ای از JSON Server) مقاوم ساخته و از بروز خطاهای `NaN` یا مقایسه‌های نادرست جلوگیری می‌کند.

### ۲. بهبود معماری مسیریابی (Routing Architecture)

- **مسیر جدید `classes/:classId/assignments`:** در نسخه قبل، دسترسی به تکالیف یک کلاس خاص صرفاً از طریق صفحه عمومی تکالیف ممکن بود. در نسخه فعلی، مسیر اختصاصی برای مشاهده تکالیف هر کلاس تعریف شده که جریان ناوبری (Navigation Flow) را بهبود می‌بخشد.
- **رفع ابهام پارامترها:** در `AssignmentsPage`، پارامتر `classId` به‌جای `id` مبهم استفاده شده و خوانایی کد و قابلیت نگهداری آن افزایش یافته است.

### ۳. اصلاح و بهبود ماژول تکالیف (Assignments)

| قابلیت                        | نسخه قبل                               | نسخه فعلی                                          |
| :---------------------------- | :------------------------------------- | :------------------------------------------------- |
| مدیریت حالت صفحه              | متغیرهای پراکنده `useState`            | آبجکت تجمیعی `PageState`                           |
| ارسال پاسخ دانشجو             | ارجاع به `editingAssignment` (باگ‌دار) | ارجاع به `submittingAssignment` (اصلاح‌شده)        |
| ستون «نمره و بازخورد» در جدول | نمایش در جدول اصلی                     | انتقال به صفحه جزئیات پاسخ‌ها                      |
| ویرایش تکلیف                  | حذف تمام پاسخ‌های دانشجویان            | حفظ پاسخ‌ها (فقط حذف تکلیف، پاسخ‌ها را حذف می‌کند) |
| دسترسی ادمین به نمرات         | محدود به استاد مالک                    | ادمین نیز مجاز به مشاهده و نمره‌دهی                |
| ناوبری پس از ثبت نمره         | بازگشت خودکار با `setTimeout`          | نمایش پیام موفقیت بدون ناوبری اجباری               |

### ۴. ارتقاء ماژول اطلاعیه‌رسانی (Announcements)

- **انعطاف‌پذیری تایپی:** پشتیبانی هم‌زمان از شناسه‌های عددی و رشته‌ای برای `classId` و `authorId`.
- **بهبود منطق فیلترینگ:** اضافه شدن شرط «نویسنده خود کاربر است» برای اطمینان از مشاهده اطلاعیه‌های ایجادشده توسط خود کاربر.
- **مدیریت دسترسی ویرایش/حذف:** تفکیک دقیق‌تر مجوزها از طریق تابع `canManageItem`.

### ۵. بهبود ماژول کلاس‌ها و جزئیات کلاس

- **دکمه «مشاهده تکالیف کلاس»:** در صفحه جزئیات کلاس (`ClassDetailsPage`)، دکمه‌ای برای دسترسی مستقیم به تکالیف آن کلاس اضافه شده است.
- **مدیریت خطای شبکه:** پیاده‌سازی تابع `getErrorMessage` برای تشخیص و نمایش پیام‌های اختصاصی خطاهای شبکه (`ERR_NETWORK`, `ECONNABORTED`).
- **فیلتر کردن کلاس‌ها در فرم اطلاعیه:** اساتید صرفاً کلاس‌های تحت تدریس خود را در فرم ایجاد اطلاعیه مشاهده می‌کنند.

### ۶. بهبودهای رابط کاربری و تجربه کاربری (UI/UX)

| مورد                    | نسخه قبل                          | نسخه فعلی                                  |
| :---------------------- | :-------------------------------- | :----------------------------------------- |
| چیدمان جدول             | `text-left`                       | `text-center` + `m-auto`                   |
| موقعیت دکمه منوی موبایل | `right-4`                         | `left-4`                                   |
| هدر                     | بدون کلاس‌های ریسپانسیو           | پشتیبانی کامل `sm:`                        |
| فرم ورود                | `useRef` + `useEffect` برای فوکوس | `autoFocus` (ساده‌سازی)                    |
| پیام‌های موفقیت/خطا     | ناهمگون                           | یکپارچه با `actionMessage` و `actionError` |

### ۷. ارتقاء وابستگی‌ها (Dependency Upgrades)

کلیه وابستگی‌های اصلی پروژه به آخرین نسخه‌های پایدار ارتقا یافته‌اند:

- **React:** `19.2.6` → `19.2.8`
- **Axios:** `1.16.1` → `1.19.0`
- **React Router DOM:** `7.16.0` → `7.18.2`
- **Vite:** `8.0.12` → `8.2.2`
- **Recharts:** `3.8.1` → `3.10.1`
- **ESLint:** `10.3.0` → `10.8.1`

### ۸. بهبود مدیریت کاربران و سرویس‌ها

- **سرویس کاربران:** کلیه توابع (`update`, `delete`, `toggleStatus`, `changeRole`) از تایپ `ID` به‌جای `number` استفاده می‌کنند.
- **سرویس اطلاعیه‌ها:** تابع `isSeenBy` با مقایسه نرمال‌شده (`String()`) بازنویسی شده است.
- **سرویس حضور و غیاب:** پشتیبانی کامل از شناسه‌های رشته‌ای و عددی.

## ویژگی‌های کلیدی سامانه

### ۱. مدیریت کاربران و کنترل دسترسی (RBAC)

- احراز هویت امن و مدیریت نشست (Session) کاربران.
- تفکیک دقیق سطوح دسترسی برای سه نقش اصلی: **مدیر گروه (Admin)**، **استاد (Teacher)** و **دانشجو (Student)**.
- قابلیت جستجو، فیلتر، ایجاد، ویرایش و تغییر وضعیت (فعال/غیرفعال) کاربران.
- جلوگیری از حذف یا غیرفعال‌سازی آخرین مدیر سیستم.

### ۲. مدیریت کلاس‌ها و جلسات آموزشی

- تعریف کلاس‌های درسی با تعیین ظرفیت، استاد مربوطه و لیست دانشجویان.
- ایجاد و مدیریت جلسات (Sessions) برای هر کلاس به تفکیک تاریخ.
- نمایش وضعیت کلاس (فعال/غیرفعال) و آمار تکمیل ظرفیت.
- دسترسی مستقیم به تکالیف هر کلاس از صفحه جزئیات.

### ۳. سیستم حضور و غیاب هوشمند

- ثبت وضعیت حضور دانشجویان (حاضر، غایب، با تأخیر) به ازای هر جلسه توسط استاد.
- محاسبه خودکار درصد حضور و غیاب هر دانشجو در هر کلاس.
- مشاهده تاریخچه حضور و غیاب توسط دانشجو در پروفایل اختصاصی.
- نوار پیشرفت بصری برای نمایش درصد حضور.

### ۴. مدیریت تکالیف و ارزیابی (Assignments)

- تعریف تکلیف با تعیین عنوان، توضیحات و مهلت ارسال (Deadline) توسط استاد.
- امکان ارسال پاسخ (Submission) توسط دانشجو و پیگیری وضعیت آن.
- سیستم نمره‌دهی و ارائه بازخورد (Feedback) توسط استاد برای هر پاسخ ارسال‌شده.
- **ویرایش تکلیف بدون حذف پاسخ‌های موجود** (بهبود یافته در نسخه `1.6.0`).
- دسترسی ادمین به نمره‌دهی و مشاهده پاسخ‌ها.

### ۵. سامانه اطلاعیه‌رسانی هدفمند

- ایجاد اطلاعیه با قابلیت تعیین مخاطب خاص (کل سیستم، یک کلاس خاص، یا نقش‌های ویژه).
- ردیابی وضعیت مشاهده (Seen/Unseen) اطلاعیه‌ها توسط کاربران هدف.
- بازنشانی وضعیت مشاهده هنگام ویرایش اطلاعیه.
- فیلترینگ هوشمند بر اساس نقش، کلاس و مخاطب هدف.

### ۶. داشبورد و پروفایل کاربری

- **پروفایل دانشجو:** نمای کلی از آمار حضور، درصد شرکت در جلسات و تاریخچه کامل.
- **پروفایل عمومی:** نمایش اطلاعات کاربری، نقش و وضعیت حساب.

## ساختار دایرکتوری پروژه (Architecture)

پروژه بر اساس اصل جداسازی دغدغه‌ها (Separation of Concerns) سازماندهی شده است:

```text
src/
├── components/          # کامپوننت‌های قابل استفاده مجدد
│   ├── common/          # کامپوننت‌های مشترک (Header, Sidebar, Loading, EmptyState)
│   └── ui/              # کامپوننت‌های UI پایه (Button, Modal, Table, Card, ...)
├── context/             # مدیریت وضعیت سراسری (AuthContext, AuthProvider)
├── data/                # داده‌های ثابت و پیکربندی‌های اولیه
├── layouts/             # چیدمان‌های اصلی صفحه (MainLayout)
├── pages/               # کامپوننت‌های سطح صفحه دسته‌بندی‌شده بر اساس ماژول
│   ├── announcements/   # ماژول اطلاعیه‌ها
│   ├── assignments/     # ماژول تکالیف و پاسخ‌ها
│   ├── attendance/      # ماژول حضور و غیاب
│   ├── auth/            # صفحه ورود
│   ├── classes/         # ماژول کلاس‌ها و جلسات
│   ├── dashboard/       # داشبورد
│   ├── profile/         # پروفایل کاربری
│   └── users/           # مدیریت کاربران
├── routes/              # تعریف مسیرها و محافظ‌های دسترسی
├── services/            # لایه ارتباط با API
│   ├── api/             # تنظیمات Axios و API پایه
│   └── modules/         # سرویس‌های اختصاصی هر ماژول
├── types/               # تعاریف نوع و اینترفیس‌های TypeScript
└── utils/               # توابع کمکی و ابزارهای کاربردی
```

## راهنمای نصب و راه‌اندازی

برای اجرای پروژه در محیط توسعه، مراحل زیر را به ترتیب دنبال نمایید:

### پیش‌نیازها

- **Node.js** نسخه `18.x` یا بالاتر
- **npm** نسخه `9.x` یا بالاتر

### مراحل اجرا

**۱. نصب وابستگی‌ها:**

```bash
npm install
```

**۲. راه‌اندازی سرور شبیه‌سازی داده (ترمینال اول):**

```bash
npm run server
```

> این دستور یک RESTful API محلی روی پورت `3001` ایجاد می‌کند.

**۳. اجرای محیط توسعه فرانت‌اند (ترمینال دوم):**

```bash
npm run dev
```

> پروژه روی پورت `5173` در دسترس خواهد بود.

**۴. ساخت نسخه نهایی (Production Build):**

```bash
npm run build
npm run preview
```

## ملاحظات فنی و توسعه

- **مدیریت خطا:** تمامی درخواست‌های شبکه با مکانیزم‌های مدیریت خطا (Try/Catch) و نمایش پیام‌های مناسب به کاربر پوشش داده شده‌اند. در نسخه `1.6.0`، تشخیص خطاهای شبکه (`ERR_NETWORK`, `ECONNABORTED`) به‌صورت اختصاصی پیاده‌سازی شده است.
- **اعتبارسنجی:** فرم‌ها دارای اعتبارسنجی در سمت کلاینت (Client-side Validation) جهت جلوگیری از ارسال داده‌های ناقص یا نامعتبر هستند.
- **واکنش‌گرایی:** رابط کاربری با استفاده از کلاس‌های کاربردی Tailwind CSS برای نمایش بهینه در دستگاه‌های موبایل، تبلت و دسکتاپ بهینه‌سازی شده است.
- **انعطاف‌پذیری تایپی:** با تغییر تایپ `ID` به `number | string`، سامانه در برابر ناهمگونی داده‌های سرور مقاوم شده است.
- **معماری سرویس‌محور:** کلیه درخواست‌های HTTP در لایه `services` متمرکز شده‌اند و تغییر بک‌اند (از Mock به واقعی) بدون تغییر در لایه نمایش امکان‌پذیر است.
